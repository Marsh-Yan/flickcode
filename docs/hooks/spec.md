# Agent 生命周期 Hooks Spec

## 背景

FlickCode 已具备会话管理、Agent 轮次循环、消息历史、工具执行、权限检查、上下文管理和 YAML 配置能力，但这些生命周期节点目前没有统一的自动化扩展机制。

格式化、上下文补充、外部通知和工具安全检查等重复工作，仍需要用户手动执行，或分别硬编码到不同模块中。这会导致触发时机不一致、策略分散、难以复用，也难以判断某项自动化为何执行或未执行。

本功能引入声明式 Hooks。每条规则以“事件 + 可选条件 + 动作”描述，在 Agent 生命周期的确定节点自动运行。系统统一负责规则加载、校验、匹配、执行、故障隔离和诊断，使自动化行为可配置、可预测、可观察。

## 目标

- 使用 YAML 声明 Hook 规则，事件和动作必填，条件可省略。
- 覆盖系统、会话、轮次、完整消息和工具五类生命周期节点。
- 使用与权限规则共享的匹配能力，支持精确、反向、正则和 glob 匹配。
- 每条条件只能选择“全部满足”或“任一满足”一种组合方式。
- 支持 Shell 命令、提示词注入、HTTP 请求和子 Agent 四类动作；子 Agent 本阶段只完成声明与校验。
- 允许工具执行前的同步 Hook 根据工具名称和参数显式拒绝调用，并将拒绝原因作为工具结果反馈给模型。
- 支持只运行一次、后台异步和命令超时控制；可能拦截工具的 Hook 必须同步运行。
- 从用户级、项目级和本地级三个来源加载规则，支持命名规则覆盖和匿名规则合并。
- Hook 自身的失败、超时或无效拦截响应只产生诊断，不中断 Agent 主流程。
- 保持现有权限、Agent Loop、上下文管理、Skill、MCP 和普通对话行为兼容。

## 功能需求

### F1：固定生命周期事件目录

系统必须提供以下事件，事件名称和触发语义保持稳定：

- 系统级：系统启动完成、系统正常关闭。
- 会话级：新会话开始、会话恢复、会话结束。
- 轮次级：用户轮次开始、用户轮次结束。
- 消息级：完整用户消息被接受、模型请求即将发送、模型完整响应已生成。
- 工具级：工具执行前、工具产生结果后。

消息事件只针对完整逻辑消息或完整模型请求触发，不对流式文本片段触发。一次用户轮次可以包含多次模型请求、模型响应和工具调用。

工具执行前事件发生在参数解析完成后、权限检查和真实执行之前。工具结果事件必须覆盖成功、执行错误、权限拒绝、Hook 拦截和未知工具等结果。

### F2：声明式规则结构

每条规则必须包含：

- `event`：一个受支持的生命周期事件。
- `action`：一个且仅一个动作。
- `if`：可选条件；省略时无条件匹配。

规则还可以声明：

- 可选 `name`，用于覆盖、诊断和运行一次状态。
- 是否只运行一次。
- 是否后台异步执行。
- 适用的超时时间。

缺少事件或动作、包含未知字段、字段类型错误或组合不合法的规则必须在加载阶段被识别。

### F3：三级加载、覆盖与信任确认

规则从以下三级来源加载：

1. 用户级配置；
2. 项目级配置；
3. 本地级配置。

更接近当前项目的来源优先。有名称的规则由更高层级的同名规则完整覆盖；匿名规则始终追加。

用户级和本地级规则视为用户可信配置。项目级规则首次准备生效时，必须请求一次项目整体信任确认；决定只在当前会话内有效，本阶段不持久化。未获信任的项目级规则不得执行，但不得影响用户级和本地级规则。

### F4：共享条件匹配能力

Hooks 与权限规则必须使用同一个通用匹配能力。条件可以读取当前事件公开的上下文字段，并支持：

- 精确匹配；
- 反向匹配；
- 正则匹配；
- glob 匹配。

一组条件必须明确选择“全部满足”或“任一满足”，不得在同一组内混用两种逻辑。省略条件表示无条件匹配。

无效正则、未知事件字段、空条件组或不合法的逻辑组合必须在集中校验阶段报告。

现有权限 YAML 的 `tool + pattern + allow/deny` 行为必须继续兼容；升级共享匹配能力不能改变已有规则的匹配结果和优先级。

### F5：稳定的事件上下文

每个事件必须提供与其层级相关的只读上下文，供条件和动作使用：

- 系统：工作目录、配置来源和启动状态。
- 会话：会话标识、新建或恢复状态。
- 轮次：轮次编号、Agent 模式和结束原因。
- 消息：角色、完整内容及消息所处阶段。
- 工具：调用标识、工具名称、完整参数和规范化结果。

动作可以通过统一的模板引用这些字段。未知变量或无法展开的模板属于 Hook 失败，只记录诊断，不中断主流程。

敏感字段不得因为上下文模板、错误或日志而被意外输出。

### F6：Shell 命令动作

Shell 动作必须声明待执行命令，并能够接收当前事件上下文。系统必须收集退出状态、标准输出、标准错误、耗时和超时结果，用于诊断或工具前置拦截判定。

命令失败、退出码非零或超时均属于 Hook 自身失败，默认只记录日志并继续 Agent 主流程。

### F7：提示词注入动作

提示词动作必须声明待注入内容，并支持事件上下文模板。

注入生命周期由事件决定：

- 系统启动或会话开始产生的提示词在当前会话持续有效；
- 轮次、消息和工具事件产生的提示词只进入下一次模型请求。

注入内容不得写入持久化对话历史，也不得作为普通用户或助手消息进入会话归档。相同触发序列下，提示词组合顺序必须稳定。

### F8：HTTP 请求动作

HTTP 动作必须声明请求地址，并允许声明请求方法、请求头、请求体和超时。请求字段支持事件上下文模板。

系统必须记录响应状态、可用的响应内容、耗时和失败原因，同时对凭据和敏感请求头进行脱敏。连接错误、超时、非成功状态或非法响应默认只记日志，不影响 Agent 主流程。

### F9：子 Agent 动作占位

系统必须能够解析和校验子 Agent 动作的声明，并清晰标记其当前不可执行。

匹配到此类规则时，只产生“本阶段尚未支持执行”的诊断，不得创建子 Agent，也不得中断主流程。真实运行留到 SubAgent 功能对接时实现。

### F10：执行控制

规则可以声明以下控制项：

- `once`：在当前会话生命周期内最多成功调度一次；应用重启或重新恢复后可以再次运行。
- `async`：动作进入后台执行，事件分发无需等待完成。
- `timeout`：限制 Shell 命令的最长执行时间；HTTP 动作使用自身请求超时。

可能影响工具是否继续执行的工具前置 Hook 禁止异步。加载时发现该组合必须判为无效配置。

本阶段不持久化 `once` 状态，也不提供显式优先级。

### F11：工具执行前拦截

同步 Shell 或 HTTP 动作在工具执行前事件中，可以返回统一的结构化判定：

- 显式 `allow`：继续检查后续规则及原有权限策略。
- 显式 `deny`：停止该工具的真实执行，并携带非空拒绝原因。
- 没有合法判定：视为普通动作结果，继续执行。

只有语法合法的显式 `deny` 能够拦截工具。非零退出、超时、网络错误、非成功 HTTP 状态、空响应或非法结构均属于 Hook 失败，必须记录后放行。

发生拦截时，拒绝原因必须转换为普通失败工具结果反馈给模型，使模型能够解释原因并调整方案。随后仍触发工具结果事件。

匹配的前置规则按稳定顺序同步执行；遇到首个显式拒绝后停止执行剩余前置规则。

### F12：稳定合并与执行顺序

未被覆盖的规则按“用户级 → 项目级 → 本地级”及各文件中的声明顺序形成稳定执行序列。命名覆盖后的规则按最终生效来源的位置参与排序。

同一事件的同步动作按照该序列执行。异步动作按照同一序列调度，但不承诺完成顺序。

本阶段不支持用户声明显式优先级。

### F13：集中校验与原子加载

所有来源必须先完成解析、合并和集中校验，再形成可执行规则快照。模型和 Agent 主流程不得看到只加载了一部分的规则集合。

单条无效规则不得阻止其他有效规则加载；诊断必须指出规则名称或位置、来源和失败原因。若重新加载产生错误，系统必须保留上一份完整有效快照，避免半更新状态。

### F14：故障隔离与诊断

Hook 动作抛出异常、退出失败、超时、模板错误或返回非法拦截结果时：

- 记录规则身份、事件、动作类型、来源、耗时和脱敏后的原因；
- 不把异常传播到 Agent 主流程；
- 不改变原有权限判定；
- 不阻止后续正常生命周期处理。

后台任务的失败也必须进入同一诊断通道，不能形成无人观察的异常。

## 非功能需求

### N1：确定性

- 相同配置、事件和上下文必须产生相同的规则集合、匹配结果和同步执行顺序。
- 规则发现和合并不得依赖文件系统返回顺序。
- 提示词组合、首个拦截规则和诊断展示顺序必须稳定。
- 异步动作只允许完成时间不确定，其调度顺序仍须稳定。

### N2：安全性

- 未获信任的项目级规则不得执行任何动作。
- Hook 上下文、命令输出、HTTP 请求与响应、错误及日志必须对凭据和敏感字段脱敏。
- HTTP 请求只能发送到规则明确声明的地址，不得隐式跟随配置外的目标。
- Shell 动作必须保持明确的工作目录和超时边界。
- Hook 不得绕过原有工具权限、黑名单、沙箱或高风险确认；Hook 放行只表示继续进入原有安全链路。
- 只有合法的显式拒绝结果可以拦截工具，Hook 故障不得被误判为安全拒绝。

### N3：故障隔离

- 单条规则的解析、校验、匹配或执行失败不得使会话、轮次、模型请求或工具流程崩溃。
- 一个异步动作失败不得取消其他异步动作。
- Hook 系统初始化失败时，FlickCode 必须能够在禁用 Hooks 的状态下继续运行，并给出明确诊断。
- 正常关闭时应尽力完成或取消后台任务，但清理失败不得阻止主程序退出。

### N4：响应与资源边界

- 未配置规则或没有规则匹配时，生命周期分发不得产生外部进程或网络请求。
- 同步 Hook 必须受超时控制，不能无限阻塞 Agent。
- 后台执行必须有明确的任务数量和资源回收边界，不能无限创建线程、进程或连接。
- 工具前置拦截的额外延迟应只来自实际匹配的同步规则。
- 规则加载、校验和条件匹配不得调用模型。

### N5：兼容性

- 没有 Hook 配置时，FlickCode 的启动、会话恢复、Agent Loop、消息历史、上下文压缩、权限处理、Skill、MCP 和工具执行行为必须与改造前一致。
- 现有权限规则文件无需修改即可继续使用，已有 glob 匹配和三级优先级保持不变。
- Anthropic 与 OpenAI Provider 的消息及工具结果格式都必须获得等价行为。
- 交互式终端和非交互输入必须共享相同的 Hook 触发语义。
- 实现继续支持项目声明的 Python 3.8 及以上版本。

### N6：可观察性

诊断能力必须能够展示：

- 每条生效规则的名称或位置、来源、事件和动作类型；
- 命名规则的覆盖关系；
- 被跳过规则及原因；
- 项目级规则的当前信任状态；
- 最近执行结果、耗时、失败或拦截原因；
- 当前会话中已经触发的 `once` 规则；
- 尚未执行的子 Agent 占位动作；
- 后台动作的运行和结束状态。

用户不应通过逐行读取内部日志才能判断某条规则是否加载、匹配、执行或失败。

### N7：可测试性

- 配置发现、三级覆盖、信任判断、集中校验和重新加载快照必须能使用临时目录测试。
- 通用匹配器必须独立验证精确、反向、正则、glob、全部满足和任一满足。
- Shell、HTTP、提示词和子 Agent 占位动作必须可使用假执行器、假网络和可控时钟测试。
- 每个生命周期事件必须能由假 Session、假 Provider 和假工具稳定触发。
- 拦截、Hook 故障放行、工具结果回流和提示词作用域必须无需真实模型或真实网络即可验证。
- 测试必须覆盖 Windows 与 POSIX 的路径及命令差异。

### N8：可维护性与扩展性

- 生命周期事件定义、规则加载、条件匹配、动作执行和诊断之间必须保持清晰边界。
- 权限与 Hooks 共享匹配能力，但不得形成相互依赖的业务规则。
- 新增事件或动作类型时，不应改变现有规则含义。
- 子 Agent 动作未来接入真实运行时，不应要求修改现有 YAML 的核心三要素。
- 本阶段不得为显式优先级、`once` 持久化或尚未实现的远程规则分发预留复杂协议。

## 不做的事

- 不真实启动子 Agent；仅解析、校验并诊断子 Agent 动作声明。
- 不持久化 `once` 已执行状态；应用重启或会话恢复后可以重新触发。
- 不提供规则的显式优先级、依赖关系或前后编排语法。
- 不监听配置文件变化，也不要求运行中自动热更新；重新加载能力只需保证完整快照和失败回退。
- 不对流式文本 delta、思考片段或 token 级事件触发 Hook。
- 不允许 Hook 直接修改工具名称、工具参数或既有工具结果；本阶段只允许显式拦截并生成拒绝结果。
- 不把提示词注入内容写入主对话历史、会话归档或上下文摘要。
- 不允许 Shell 或 HTTP 动作通过普通失败、超时或异常隐式拦截工具。
- 不提供条件脚本、任意代码表达式或混合 `all`/`any` 的嵌套逻辑树。
- 不提供定时任务、cron、文件变化监听或生命周期之外的自定义事件。
- 不实现 HTTP 自动重试、OAuth、凭据管理、复杂重定向策略或响应流处理。
- 不实现跨项目共享的远程 Hook 市场、规则下载或规则版本管理。
- 不提供图形化规则编辑器；规则继续通过 YAML 管理。
- 不因本功能重写 Agent Loop、权限系统、上下文管理、Skill 或 MCP 的核心业务语义。
- 不将“项目级 Hook 信任”持久化；持久化信任可在后续安全配置章节设计。

## 验收标准

- **AC1 — 生命周期覆盖（F1）**：运行一次包含两轮模型请求和一次工具调用的完整用户轮次；观察系统按定义触发会话、轮次、完整消息、工具前后事件，且不为流式文本片段触发事件。
- **AC2 — 规则最小结构（F2）**：加载仅包含 `event + action` 的规则时能够无条件触发；增加 `if` 后只在条件满足时触发。缺失事件、缺失动作或声明多个动作时，规则被跳过并显示明确原因。
- **AC3 — 三级来源与覆盖（F3）**：在用户级、项目级和本地级分别放置命名及匿名规则；观察同名规则由更近层级完整覆盖，匿名规则全部保留。项目级规则未获信任时不执行，确认信任后在当前会话生效，重新启动后再次要求确认。
- **AC4 — 通用匹配器（F4）**：分别使用精确、反向、正则和 glob 条件触发规则，并验证 `all` 与 `any` 的结果。加载混用逻辑、无效正则或未知字段的规则时产生校验错误。运行已有权限规则样例时，匹配结果和优先级与改造前一致。
- **AC5 — 事件上下文与模板（F5）**：在不同层级动作中引用会话标识、轮次、完整消息、工具名称、参数和结果；观察模板得到正确值。引用未知变量时动作失败但 Agent 继续运行，诊断中不出现配置的测试密钥。
- **AC6 — Shell 动作（F6）**：匹配事件后运行一个会输出标准输出、标准错误和指定退出码的命令；观察系统记录退出状态和耗时。运行超时或非零退出命令时只产生 Hook 失败诊断，原生命周期继续执行。
- **AC7 — 提示词作用域（F7）**：在会话开始注入长期提示词，并在工具结果后注入一次性提示词；观察长期内容出现在本会话后续模型请求中，一次性内容只出现在下一次请求中，两者均不进入持久化消息、归档或摘要。
- **AC8 — HTTP 动作（F8）**：向可控假服务发送带模板化方法、请求头和请求体的请求；观察服务收到正确事件数据。服务返回错误状态、非法响应或发生超时时，Agent 主流程继续，日志中的敏感请求头已脱敏。
- **AC9 — 子 Agent 占位（F9）**：加载并触发合法的子 Agent 动作；观察配置通过校验、系统明确记录“尚未支持执行”，且没有创建子会话或启动任何 Agent。
- **AC10 — 执行控制（F10）**：同一会话多次触发 `once` 规则时只成功调度一次；重新启动或恢复后可再次调度。异步规则不阻塞事件返回。工具前置拦截规则声明异步时在加载阶段被拒绝。
- **AC11 — 工具拦截（F11）**：工具前置 Shell 或 HTTP 动作返回合法 `deny` 和原因时，真实工具及后续前置规则均不执行，模型收到包含该原因的失败工具结果，工具结果事件仍被触发。
- **AC12 — 故障放行（F11、F14）**：让工具前置动作分别发生非零退出、超时、网络错误和非法判定响应；观察每次都记录 Hook 失败、继续进入原权限检查和工具流程，不产生误拦截。
- **AC13 — 稳定顺序（F12）**：用相同的三级规则配置重复启动并触发同一事件；观察同步动作、提示词组合和首个拒绝规则顺序完全一致。异步动作的调度顺序一致，但允许完成顺序不同。
- **AC14 — 集中校验与完整快照（F13）**：配置中同时包含有效和无效规则时，有效规则可执行，无效规则被单独报告。重新加载一份整体无法形成有效快照的配置时，系统继续使用上一份完整快照，不出现部分新旧规则混合。
- **AC15 — 故障隔离与诊断（F14）**：让不同动作分别抛出异常或后台失败；观察会话、轮次、消息和工具主流程均可继续，诊断能够指出规则身份、来源、事件、动作类型、耗时和脱敏原因。
- **AC16 — 无配置兼容性**：移除全部 Hook 配置后，运行现有会话、权限、Agent Loop、上下文、Skill、MCP 和工具测试；观察行为与功能引入前一致，且不会启动额外进程或发出网络请求。
- **AC17 — 端到端安全场景**：配置一条项目级工具前置规则，仅拒绝参数命中特定正则的命令。首次进入项目时先请求整体信任；确认后，安全命令继续经过原权限系统并执行，危险命令被 Hook 拒绝、拒绝原因反馈给模型，随后模型可以选择安全替代方案并完成当前轮次。
