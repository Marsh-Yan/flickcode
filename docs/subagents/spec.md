# FlickCode 子 Agent 委派 Spec

## 背景

FlickCode 已具备 Agent Loop、工具注册与过滤、权限引擎、Hook 后台执行、会话日志，以及隔离 Skill 子会话等基础能力，但尚未提供面向主 Agent 的通用任务委派机制。

复杂任务只能在主 Agent 的单一对话上下文中持续执行，探索过程、工具结果和中间推理会不断占用主上下文。现有隔离 Skill 绑定特定工作流，Hook 的子 Agent 动作也仅为不可执行的占位，均不能承担通用子任务委派。

## 目标

- 提供稳定、统一的 Agent 工具，让主 Agent 委派独立子任务。
- 支持定义式与 Fork 式两种启动方式，同时保持工具接口和工具列表稳定。
- 让子 Agent 的消息、权限状态、文件读取缓存和用量统计彼此隔离。
- 共享 LLM 客户端、Hook 引擎和文件系统等基础设施，避免不必要的重复初始化。
- 让子 Agent 非交互地持续运行至完成、安全终止或达到限制。
- 支持前台转后台以及后台任务的状态、结果和用量追踪。
- 子任务完成后只向主对话投递结构化摘要；完整结果按任务 ID 查询，避免重新污染主上下文。
- 为以后接入 Worktree 隔离、多 Agent 团队编排和跨会话任务持久化保留清晰扩展边界。

## 功能需求

### F1：统一委派入口

系统必须向主 Agent 暴露一个稳定的 Agent 工具。该工具通过类型参数选择“定义式”或“Fork 式”，不得因角色数量、加载来源或运行状态而动态增删工具。

每次调用必须明确包含子任务描述；定义式还必须指定角色，Fork 式不得指定角色。

### F2：角色定义格式

定义式角色必须使用带 YAML frontmatter 的 Markdown 文件声明：

- 角色名
- 用途说明
- 工具白名单
- 工具黑名单
- 模型：继承父 Agent，或选择 `haiku`、`sonnet`、`opus`
- 最大运行轮次
- 权限模式

Markdown 正文必须作为角色的固定系统提示，贯穿该子 Agent 的整个生命周期。

无效定义不得进入可用角色目录，并必须产生可诊断的错误；单个无效角色不得阻止其他合法角色加载。

### F3：多来源加载与覆盖

系统必须从项目级、用户级、内置和插件四类来源加载角色。同名角色按以下优先级选择唯一生效版本：

`项目级 > 用户级 > 内置 > 插件`

低优先级定义被覆盖时不得与高优先级定义合并；系统必须能够说明最终角色来自哪里，以及哪些定义被覆盖或拒绝。

### F4：定义式启动

定义式子 Agent 必须：

- 从空白消息历史开始；
- 使用所选角色的固定系统提示；
- 接收本次子任务描述；
- 按角色配置选择模型、工具范围、最大轮次和权限模式；
- 不继承父对话的普通消息、临时提示或运行时状态。

父任务的必要环境信息只能通过明确、受控的启动上下文传入，不得隐式复制父对话。

### F5：Fork 式启动

Fork 式子 Agent 必须：

- 继承父 Agent 在委派发生前已经完成的对话历史；
- 继承父 Agent 当时可见的工具集和运行模式；
- 在继承历史之后追加本次子任务；
- 保持继承前缀的内容与顺序稳定，使首次模型请求具备命中提供商 Prompt Cache 的条件；
- 使用父 Agent 的模型、权限基线和最大轮次默认值，除非全局安全限制进一步收紧。

Fork 不得复制父 Agent 正在生成但尚未完成的半成品消息。

### F6：运行时隔离与基础设施共享

每个子 Agent 必须拥有独立的：

- 消息历史；
- 权限决策与临时授权记录；
- 文件读取缓存；
- 输入、输出及思考 Token 计数；
- 轮次计数、停止原因和错误状态；
- 取消状态。

子 Agent 可以共享：

- 已配置的 LLM 通信基础设施；
- Hook 执行基础设施；
- 文件系统访问入口；
- 不可变配置和工具实现。

共享设施不得导致一个子 Agent 的运行时状态泄漏到父 Agent 或其他子 Agent。

### F7：非交互“跑到底”

子 Agent 启动后必须非交互执行，不得向用户发起确认或追问：

- 模型不再调用工具时，视为正常完成；
- 达到最大轮次时，必须以受限状态结束；
- 权限模式不允许的操作必须被拒绝并反馈给子 Agent，不得等待人工授权；
- 提供商错误、工具错误和内部异常必须形成明确的失败结果；
- 取消请求必须使任务尽快进入已取消状态。

### F8：多层工具过滤

子 Agent 的最终工具集必须依次受到以下限制，任一上层限制均不得被下层重新放开：

1. 全局禁止工具；
2. 当前角色或 Fork 来源工具集的限制；
3. 后台执行白名单。

所有子 Agent 均不得获得可再次创建子 Agent 的委派工具，防止无限嵌套。工具白名单与黑名单冲突时，黑名单优先。

### F9：前台与后台执行

系统必须支持三种进入后台的方式：

- 调用时显式指定后台运行；
- 前台等待超过配置阈值后自动转入后台；
- 用户将正在前台运行的任务手动切换到后台。

Fork 式必须始终后台运行。若调用方请求 Fork 前台运行，系统必须明确告知其已按规则转为后台，而不是静默忽略。

前台转后台不得重启任务、丢失消息、重置用量或改变任务 ID。

### F10：后台任务管理

后台任务管理器必须为每个任务分配唯一任务 ID，并追踪：

- 父任务与子任务关系；
- 类型与角色；
- 排队、运行、完成、失败、取消等状态；
- 创建、开始和结束时间；
- 最终摘要与完整结果；
- 停止原因和错误；
- 各类 Token 用量及总轮次。

主 Agent 和用户必须能够按任务 ID 查询状态、读取完整结果和请求取消。查询不得把完整结果自动写入主对话历史。

### F11：异步结果通知

后台任务结束后，系统必须向仍在运行的主会话投递一次结构化通知，内容包括：

- 任务 ID；
- 最终状态；
- 简短摘要；
- 停止原因；
- 用量概览；
- 查询完整结果的提示。

完整输出不得自动注入主对话。重复完成回调不得产生重复通知。

若父会话已经关闭，本阶段只需安全记录任务结果，不要求跨会话补发通知。

### F12：Hook 与可观测性

子 Agent 执行必须进入现有生命周期观测体系，使 Hook 能区分父 Agent 与子 Agent，并获得任务 ID、父任务 ID、角色、运行类型和最终状态等非敏感元数据。

子 Agent 的错误、权限拒绝、后台切换和完成结果必须进入统一诊断通道；诊断信息不得泄露 API Key、鉴权头或其他敏感配置。

### F13：资源与关闭行为

系统必须限制并发子 Agent 数量和后台排队容量。容量耗尽时，新任务必须被明确拒绝，不得无限排队。

主程序正常关闭时，系统必须停止接受新任务，并对运行中任务执行有界等待或取消；清理失败不得造成无限阻塞。

## 非功能需求

### N1：接口稳定性

统一 Agent 工具的名称、基础参数结构和返回结果结构必须稳定。新增、删除或覆盖角色不得改变主 Agent 可见的工具列表，也不得要求重建主 Agent 会话。

### N2：安全隔离

所有子 Agent 权限只能等于或严于父级及全局安全策略。角色配置、Fork 继承或后台模式均不得绕过全局禁止项、路径边界、敏感信息脱敏和工具调用审计。

### N3：确定性

在输入文件和配置不变时：

- 角色加载结果及覆盖顺序必须确定；
- 工具过滤结果必须确定；
- 前台或后台选择规则必须确定；
- 同一任务的终态和通知只能写入一次。

### N4：有界资源

子 Agent 的并发数、排队数、最大轮次、前台等待时间、关闭等待时间和结果保存大小都必须存在有限上界。

超出限制时必须降级、截断或拒绝，并保留明确诊断；不得无限创建线程、任务、消息或缓存。

### N5：缓存友好

Fork 首次请求必须尽可能复用父 Agent 最近一次请求的稳定前缀，避免无意义的序列化差异、消息重排或系统提示重建破坏 Prompt Cache。

当提供商返回缓存用量信息时，系统必须将其纳入任务用量记录；未命中缓存不得影响任务正确性。

### N6：响应性

前台子 Agent 运行不得冻结用户界面。显式转后台、超时自动转后台和手动转后台都必须及时返回任务 ID，使主会话能够继续接受输入。

后台状态查询和取消操作不得等待子 Agent 当前轮次自然结束后才响应。

### N7：可靠性

单个子 Agent 的崩溃、超时、权限拒绝或结果通知失败不得终止父 Agent、其他子 Agent 或主程序。

任务状态必须单向进入合法终态；完成、失败或取消后的任务不得重新回到运行状态。

### N8：兼容性

引入子 Agent 后，现有普通 Agent 对话、Skill、Hook、权限规则、MCP 工具、上下文管理和会话日志行为必须保持兼容。

现有 Hook 中合法的子 Agent 声明格式应保留，为后续接入真实运行器提供兼容路径；本阶段不要求 Hook 自动启动子 Agent。

### N9：可观测性

每个子 Agent 必须可通过任务 ID 关联其生命周期事件、诊断、用量和父任务。日志与用户可见状态必须区分正常完成、达到轮次上限、失败和取消。

敏感信息不得出现在任务摘要、通知、诊断或持久化结果中。

### N10：可测试性

角色加载、覆盖规则、两类启动上下文、工具过滤、权限隔离、后台切换、状态迁移、取消、通知去重及资源上限必须能够使用替代模型、替代工具、可控时钟和内存任务存储进行确定性测试，不依赖真实网络调用。

### N11：可扩展性

本阶段的任务身份、运行上下文和调度边界必须允许未来增加 Worktree 文件隔离、多 Agent 团队编排和跨会话持久化，而无需改变统一 Agent 工具的基本调用方式。

## 不做的事

- 不为子 Agent 创建独立 Git Worktree、分支、容器或文件系统快照。
- 不隔离父子 Agent 的文件写入；它们仍共享同一项目文件系统，因此并发写冲突留待后续解决。
- 不实现多个子 Agent 之间的团队编排、协商、消息互发、共享计划或依赖调度。
- 不允许子 Agent 再创建子 Agent；仅支持一层父子关系。
- 不持久化后台任务队列和运行状态；主程序重启后不恢复未完成任务。
- 不跨会话补发完成通知，也不保证关闭父会话后仍能从新会话查询旧任务。
- 不让子 Agent 在执行中向用户申请权限、追问需求或等待人工输入。
- 不新增可视化角色编辑器、任务控制面板或复杂编排 UI；仅提供完成本阶段行为所需的调用、查询、取消和手动转后台入口。
- 不实现跨进程、跨机器或分布式子 Agent 调度。
- 不保证每次 Fork 都实际命中提供商缓存；系统只保证构造缓存友好的稳定前缀，并记录提供商返回的缓存用量。
- 不在本阶段让 Hook 的 `subagent` 动作真正启动子 Agent，只保留未来兼容接入点。
- 不改变现有 Skill 的共享或隔离执行语义，也不把 Agent 角色与 Skill 合并为同一种定义。
- 不支持运行时修改一个已经启动的子 Agent 的角色、模型、工具限制、最大轮次或权限模式。

## 验收标准

### AC1：统一工具稳定性（F1、N1）

在角色目录为空、增加角色、删除角色、覆盖同名角色后分别启动或刷新系统：

- 主 Agent 始终只看到同一个 Agent 委派工具；
- 工具名称和基础参数结构不变；
- 定义式与 Fork 式均通过类型参数进入正确路径；
- 缺少任务、定义式缺少角色或 Fork 式错误指定角色时，返回明确校验错误。

### AC2：角色定义解析（F2）

分别加载完整角色、缺少必填字段的角色、frontmatter 非法的角色和模型值非法的角色：

- 完整角色可被调用，正文全程作为其固定系统提示；
- 无效角色不可调用，并产生包含来源与原因的诊断；
- 其他合法角色仍能正常加载和运行。

### AC3：多来源覆盖（F3、N3）

在插件、内置、用户和项目来源中放置同名角色：

- 最终仅项目级定义生效；
- 依次移除高优先级定义后，按用户级、内置、插件顺序回退；
- 不同来源的字段不会被合并；
- 状态或诊断能够显示生效来源及覆盖关系。

### AC4：定义式上下文（F4）

在父对话含有多轮历史和临时提示时启动定义式子 Agent：

- 子 Agent 首条上下文只包含固定角色、受控环境信息和本次任务；
- 父对话普通消息、临时提示、Token 计数和临时权限不出现在子 Agent 中；
- 角色指定的模型、工具、轮次和权限设置生效。

### AC5：Fork 上下文与缓存（F5、N5）

在父 Agent 完成若干轮对话后启动 Fork：

- 子 Agent 的首次请求以前缀形式保留委派前已完成的父对话历史；
- 未完成消息不会被复制；
- 本次任务追加在继承历史之后；
- Fork 自动进入后台并继承父工具视图；
- 若替代提供商返回缓存读取用量，该用量被记录到任务状态中。

### AC6：状态隔离（F6）

并发启动两个子 Agent，并让它们读取相同文件、产生不同权限拒绝和不同 Token 用量：

- 两者的消息、文件读取缓存、临时权限、轮次、取消标记和用量互不影响；
- 父 Agent 的对应状态保持不变；
- 两者仍通过共享基础设施访问同一项目文件系统。

### AC7：非交互运行（F7）

分别模拟模型正常停止、持续调用工具直到轮次上限、请求无权工具、提供商失败和用户取消：

- 任务分别进入完成、受限、失败或取消终态；
- 权限拒绝不会弹出确认或等待用户；
- 每个结果包含准确停止原因；
- 任一异常都不会使父会话停止工作。

### AC8：工具过滤与禁止嵌套（F8、N2）

构造全局禁止、角色白名单、角色黑名单、Fork 继承集和后台白名单相互冲突的场景：

- 最终工具集等于各层限制的安全交集；
- 黑名单优先于白名单；
- 全局禁止项无法被角色配置重新启用；
- 所有子 Agent 均看不到或无法调用 Agent 委派工具；
- 被过滤工具的伪造调用也会在执行前遭拒绝。

### AC9：三种后台切换（F9、N6）

分别执行显式后台、前台超时自动转后台和用户手动转后台：

- 三种方式都及时向父会话返回任务 ID；
- 转后台前后任务 ID、消息、轮次和用量连续；
- 任务没有重启或重复执行；
- Fork 请求即使声明前台，也明确返回“已强制后台”的结果。

### AC10：任务查询与取消（F10）

对排队、运行、完成、失败和取消任务执行查询：

- 返回正确状态、父子关系、类型、角色、时间、停止原因、轮次和用量；
- 完成任务可按 ID 读取完整结果；
- 查询完整结果不会自动增加父对话消息；
- 对可取消任务发起取消后，任务最终进入取消状态；
- 对未知 ID 和已终止任务执行非法操作时返回明确结果。

### AC11：异步通知（F11）

让后台任务正常完成，并模拟重复完成回调：

- 父会话只收到一次结构化通知；
- 通知包含任务 ID、终态、摘要、停止原因、用量概览和查询提示；
- 完整输出不在通知或父对话历史中；
- 父会话已关闭时，结果仍被安全记录且不会尝试跨会话补发。

### AC12：生命周期与脱敏（F12、N9）

观察子 Agent 从创建到结束的生命周期事件：

- 事件可通过任务 ID 关联，并包含父任务、运行类型、角色和最终状态；
- Hook 能区分父 Agent 与子 Agent；
- 权限拒绝、后台切换、错误和完成均产生可诊断记录；
- API Key、鉴权头及测试注入的敏感值不会出现在日志、通知、摘要或结果诊断中。

### AC13：容量和关闭（F13、N4）

将并发与排队容量设为小值并提交超量任务：

- 容量内任务正常排队或运行；
- 超量任务立即被明确拒绝；
- 任务数量和工作线程不会无界增长；
- 关闭时停止接收新任务，并在有限时间内完成有界等待或取消；
- 无响应任务不会阻止主程序退出。

### AC14：失败隔离与状态一致性（N7）

让一个后台子 Agent 崩溃，同时运行父 Agent 和另一个子 Agent：

- 仅故障任务进入失败状态；
- 其他 Agent 继续运行；
- 已进入完成、失败或取消的任务无法回退为排队或运行；
- 重复结束事件不会改写首次确定的终态。

### AC15：现有功能回归（N8）

运行现有普通对话、Agent Loop、Skill、Hook、权限、MCP、上下文和会话日志测试：

- 现有测试继续通过；
- 普通主 Agent 不使用委派工具时行为不变；
- Hook 的合法 `subagent` 声明仍可解析并报告当前不可执行；
- Skill 的共享与隔离模式保持原语义。

### AC16：未来扩展边界（N11）

在不改变统一 Agent 工具基本调用格式的前提下，用替代实现接入一个模拟文件隔离器或持久化任务存储：

- 子 Agent 启动和任务查询调用方无需改变；
- 扩展只替换对应基础设施边界；
- 当前定义式、Fork 式及任务状态语义保持不变。
