# FlickCode Worktree 隔离 Spec

## 背景

FlickCode 已具备定义式与 Fork 式子 Agent、前后台任务管理、权限隔离和独立对话上下文，但父 Agent 与子 Agent 仍共享同一个项目工作目录。

当多个 Agent 并行修改同一仓库时，它们可能覆盖彼此的文件、观察到不一致的中间状态，或因共享路径相关缓存产生上下文串扰。现有子 Agent 设计已为 Worktree 隔离预留扩展边界，本阶段补齐这一能力。

## 目标

- 为声明需要隔离的定义式子 Agent 创建独立 Git Worktree，使其与主 Agent 并行修改文件时互不干扰。
- 每个隔离目录共享同一 Git 仓库，但使用独立分支和工作目录。
- 提供创建、快速恢复、进入、退出和安全删除的完整生命周期。
- 创建后按项目声明完成本地配置复制、Git hooks 配置、大型依赖软链和必要忽略文件补齐。
- 全程显式传递绝对工作目录，不改变进程级当前目录。
- 让文件、提示词、项目指令、上下文和记忆等路径相关状态天然按工作目录隔离。
- 在任务结束和后台过期清理时保护未提交修改及未推送 commit。
- 为后续合并策略、跨目录代码同步和多 Agent 并行编排提供可复用的隔离基础。

## 功能需求

### F1：角色声明隔离模式

定义式角色的 YAML frontmatter 可声明 `isolation: worktree`，表示该角色每次启动都需要独立 Worktree。未声明该字段或声明为 `shared` 的角色继续使用主 Agent 的项目目录。

隔离字段只接受 `shared` 和 `worktree`。非法值必须使该角色失效并产生可诊断错误，但不能阻止其他合法角色加载。

本阶段只有定义式子 Agent 读取该字段。Fork 式子 Agent 没有角色定义，继续共享主工作目录，Agent 工具的调用参数不因本功能发生变化。

### F2：仓库识别与创建基线

系统必须从主 Agent 的项目目录识别其所属 Git 仓库及仓库顶层目录。声明 Worktree 隔离的任务只有在项目属于合法 Git 仓库、Git 支持多工作目录且当前 `HEAD` 可解析时才能启动；否则该子任务必须明确失败，不能退化为共享目录执行。

新 Worktree 必须从创建时主工作目录的 `HEAD` commit 建立独立临时分支。主工作目录中尚未提交的修改不复制到新 Worktree，也不能在创建后影响它。

### F3：安全名称与目录边界

Worktree 使用逻辑名称定位目录，并执行以下严格校验：

- 名称总长度为 1–200 个 ASCII 字符；
- 最多包含 8 个由正斜杠 `/` 分隔的非空段，允许嵌套目录；
- 每段长度为 1–64，只允许小写字母、数字、点、下划线和连字符，且首字符必须是小写字母或数字；
- 明确拒绝 `.`、`..`、空段、反斜杠、绝对路径、盘符、前导或尾随斜杠以及解析后逃离托管根目录的名称；
- 在大小写不敏感文件系统上，大小写折叠后相同的名称不得指向两个不同 Worktree。

所有 Worktree 都必须位于仓库内部的固定托管根目录，并通过仓库本地排除规则保证该根目录不会出现在版本控制候选中。系统不得为此修改受版本控制的忽略文件。

临时分支名必须由经过校验的逻辑名称和任务身份确定性生成，并再次通过 Git 引用名校验；不得直接信任模型提供的任意分支名。

### F4：创建与快速恢复

创建同一逻辑名称必须串行化，且结果幂等：

- 目标目录不存在时，系统创建独立分支和 Worktree，写入受控元数据，然后执行环境初始化；
- 目标目录已经存在时，系统进入快速恢复路径，只读取文件系统中的受控元数据进行身份、路径和状态校验，不得调用 Git，也不得修改目录；
- 已存在目录缺少元数据、元数据损坏、仓库身份不符或记录路径不匹配时，系统必须拒绝接管，不能覆盖、删除或把它当成合法 Worktree；
- 创建或初始化中途失败时，系统必须返回明确阶段和原因，并保守保留无法证明可安全回滚的目录与分支。

受控元数据必须至少记录格式版本、仓库身份、逻辑名称、目标绝对路径、临时分支、创建基线 commit、创建时间、最后使用时间和初始化状态。

### F5：显式环境初始化规则

项目可通过仓库内的显式 Worktree 配置声明环境初始化规则。默认规则为空，不得根据常见文件名自动复制 `.env`、凭据、令牌或其他敏感文件。

初始化支持以下行为：

- 复制明确列出的本地文件或目录；
- 为明确列出的大型依赖目录创建文件系统链接，不得在链接失败时静默复制整份依赖；
- 按受限匹配规则复制被 Git 忽略但运行必需的文件；
- 让子 Worktree 使用与主工作目录一致的有效 Git hooks 路径，同时避免一个 Worktree 的配置意外覆盖其他 Worktree。

所有源路径必须位于主项目目录内，所有目标路径必须位于子项目目录内。规则不得包含绝对路径、遍历段或逃离根目录的链接目标。忽略文件补齐必须确认候选文件确实被 Git 忽略，并受文件数量和总字节数上限约束。

任一必需初始化动作失败时，子 Agent 不得开始执行；错误必须说明失败规则和已保留 Worktree 的位置。

### F6：显式工作目录传播

系统不得通过 `chdir` 或等价的进程级全局状态切换工作目录。每个 Agent 运行时必须持有不可变的工作区上下文，并将绝对项目目录作为显式 `cwd` 传给每次工具执行。

路径型工具必须以该 `cwd` 解析相对路径；命令工具和 Skill 脚本必须把该目录作为子进程工作目录；不使用本地路径的工具也必须通过统一执行入口接收工作区上下文，不得回退读取进程当前目录。

权限沙箱、Hook 动作、上下文产物和其他项目本地输出必须绑定子 Worktree 的绝对项目目录。主 Agent 和共享模式子 Agent 继续绑定主项目目录。

### F7：路径相关状态隔离

文件内容、系统提示、项目指令、项目记忆及其他依赖路径的缓存或快照必须使用规范化绝对路径作为键的一部分。相同相对路径在不同 Worktree 中必须形成不同缓存项。

缓存项还必须具有足够的内容版本信息，避免同一路径被删除后重新创建时复用过期内容。写入或编辑文件后必须使对应文件内容缓存失效。

切换主 Agent、共享子 Agent和 Worktree 子 Agent 时不得依赖全量清缓存来保证正确性。

### F8：自动进入与环境说明

定义式 Worktree 子 Agent 真正开始运行前，系统必须自动创建或恢复 Worktree、完成初始化并进入工作区生命周期。排队阶段被取消的任务不应创建 Worktree。

子 Agent 的受控系统上下文必须明确说明：

- 当前子项目绝对路径；
- Worktree 顶层绝对路径；
- 主项目绝对路径；
- 临时分支名；
- 当前处于 Worktree 隔离模式，所有文件操作必须针对子项目目录。

这些说明不得通过复制父对话的临时消息实现。

### F9：退出与任务终态

子 Agent 正常完成、达到轮次上限、失败或取消后，系统都必须执行一次幂等退出流程。退出流程不得改变子任务本身的终态，但清理错误必须作为独立诊断和工作区处置结果保留。

任务状态、结果或完成通知必须能说明该任务使用的工作区路径、分支以及最终处置：已删除、因修改保留、因未推送 commit 保留、因检查失败保留或未使用 Worktree。

### F10：变更与未推送 commit 保护

删除前必须分别检查：

- 自创建基线以来是否存在未提交修改，包括暂存、未暂存和未跟踪文件；
- Worktree 临时分支相对创建基线新增的 commit 中，是否有任何 commit 未被任意 `refs/remotes/*` 远端跟踪引用包含。

只要存在未提交修改或上述未推送 commit，自动删除和默认删除请求都必须拒绝，并返回可观察的保留原因。分支是否配置 upstream 不影响判定；没有 upstream 时仍检查所有远端跟踪引用。

环境初始化产生且按配置应被忽略的文件或链接不能被误判为用户修改。无法完成状态或远端包含性检查时必须保守视为不安全。

### F11：安全删除

安全删除只能作用于当前仓库托管根目录内、名称合法、元数据身份匹配、Git 确认为同一仓库 Worktree 且当前没有活动租约的目标。

通过全部保护检查后，系统可以移除 Worktree、删除对应临时分支并清理自身元数据。任一步失败必须停止后续破坏性动作、保留诊断，并保证重复调用不会误删其他目录或分支。

自动流程不得提供绕过变更保护的强制删除。需要丢弃修改时由上层或用户在本阶段之外明确处理。

### F12：按变更决定保留或清理

任务退出时，完全干净且没有未推送 commit 的 Worktree 应立即安全删除。存在修改、未推送 commit 或不确定状态时必须保留，供主 Agent 或用户检查。

保留不能被视为子任务失败。系统必须在结果中给出绝对路径和原因，但不得自动合并、提交、推送或同步其中的变更。

### F13：后台过期清理

系统必须在不阻塞交互流程的后台定期扫描托管目录。默认过期时间为最后使用后 7 天，项目配置可以覆盖为其他正整数天数。

每个删除候选必须依次通过三层过滤：

1. **路径过滤**：候选来自固定托管根、逻辑名称合法、规范化路径仍位于根内且已超过过期时间；
2. **归属过滤**：受控元数据完整，仓库身份、记录路径和目标目录相互一致，且没有当前活动租约；
3. **Git 与变更过滤**：Git 确认它属于当前仓库，并通过未提交修改和未推送 commit 保护。

任一层失败都必须跳过该候选；扫描不得猜测、接管未知目录或使用递归通配删除。后台清理必须支持有界关闭，单个候选失败不能中止其他候选检查。

### F14：并发与生命周期一致性

创建、恢复、退出、显式删除和后台清理对同一逻辑名称必须互斥。不同 Worktree 可以并行运行，但不得共享可变的工作区状态、文件缓存或生命周期租约。

重复退出、重复完成回调和清理线程竞态不得导致重复删除、错误分支删除或任务状态回退。正在运行的子 Agent 所持有的 Worktree 不能被后台清理。

### F15：兼容与降级边界

未声明 `isolation: worktree` 的定义式角色、全部 Fork 式子 Agent、主 Agent、Skill、MCP、Hook、权限规则和普通工具调用必须保持原有可用行为。

Worktree 专属错误只能使请求该隔离模式的子任务失败，不能终止父 Agent、其他子 Agent或整个程序。新增或删除 Worktree 角色不得改变稳定 Agent 工具的 schema。

## 非功能需求

### N1：安全性

所有外部名称、配置路径、元数据和 Git 输出都必须视为不可信输入。路径判断采用解析后的绝对路径和目录归属检查，删除操作只能接收生命周期服务产生并重新验证的对象。

日志、任务结果和错误不得输出被复制配置文件的内容、API Key、鉴权头或其他秘密。

### N2：无进程级目录切换

Worktree 生命周期、Git 调用、文件工具、搜索工具、命令工具、Skill 脚本和 Hook 动作均不得调用 `chdir`。并行任务的正确性不能依赖全局工作目录在调用期间保持不变。

### N3：确定性与幂等

相同仓库、逻辑名称和受控元数据必须解析为相同目录与分支身份。创建、快速恢复和退出可安全重试；任务终态和工作区处置各自只能完成一次。

### N4：有界资源

名称长度、嵌套层数、初始化文件数、复制总量、Git 命令时限、扫描候选数、后台周期和关闭等待都必须有有限上界。达到上限时明确拒绝或跳过，不得无限遍历、复制、等待或创建线程。

### N5：性能

目标目录已存在的快速恢复只执行有界文件系统读取，不启动 Git 子进程。后台扫描不阻塞 Agent 主循环，且只有通过前两层过滤的候选才执行 Git 检查。

### N6：跨平台

路径和子进程行为必须支持 FlickCode 当前面向的 Windows、macOS 和 Linux 环境。路径分隔、大小写敏感性和目录链接能力差异必须显式处理；链接不可创建时给出明确失败，不得静默改变语义。

### N7：隔离一致性

任意两个并行 Worktree 即使包含同名相对文件、同名指令或同名记忆索引，也不得相互读取缓存内容、覆盖上下文产物或共享权限临时状态。

### N8：可靠性

Git、初始化、Hook、工具或清理错误不得导致未知目录被接管或用户变更被删除。所有不确定状态都按保留处理，并提供足以定位阶段的诊断。

### N9：可观测性

每个隔离任务可通过任务 ID 关联逻辑名称、绝对路径、临时分支、创建或恢复结果、初始化结果、退出判断和最终处置。后台清理提供扫描、跳过、删除和失败计数，但不泄露敏感内容。

### N10：可测试性

Git 命令执行、时间、文件系统初始化和后台调度必须可替换或注入，使路径安全、恢复零 Git 调用、远端包含性判断和竞态保护可以在自动化测试中确定性验证。

## 不做的事

- 不实现 Worktree 之间或 Worktree 与主分支之间的 merge、rebase、cherry-pick 或冲突处理；上层继续显式使用 Git 合并策略。
- 不把主工作目录中的未提交修改同步到新 Worktree。
- 不实现跨 Worktree 的实时文件或代码同步。
- 不实现多 Agent 团队编排、依赖图调度或任务自动拆分。
- 不为 Fork 式子 Agent 增加 Worktree 隔离，也不扩展 Agent 工具调用 schema。
- 不自动提交、推送、创建远端分支或删除远端分支。
- 不自动复制未在项目 Worktree 配置中明确声明的本地文件，尤其不猜测敏感配置。
- 不提供自动流程可调用的强制删除或变更丢弃入口。
- 不支持同一 Worktree 被多个独立 FlickCode 进程协同租用；本阶段保证单进程内的子 Agent 并发安全，并依赖 Git 自身拒绝仓库级冲突。

## 验收标准

- **AC1（F1）**：加载包含 `isolation: worktree`、省略 isolation、`isolation: shared` 和非法 isolation 的角色，前三者分别解析为预期模式，非法角色产生诊断且其他角色仍可用。
- **AC2（F2）**：在合法 Git 仓库启动隔离角色时，从调用瞬间的 `HEAD` 创建独立分支；主目录未提交修改不出现在子目录。在非 Git 目录启动同一角色时任务明确失败且不在共享目录执行。
- **AC3（F3）**：合法嵌套名称可以定位托管根内目录；针对 `../x`、`a//b`、反斜杠、绝对路径、盘符、超长段和大小写碰撞的输入全部拒绝，且托管根不出现在主工作目录的 Git 状态中。
- **AC4（F4）**：首次创建产生 Worktree 与完整元数据；同一路径再次创建仅进行文件系统读取，Git fake 的调用次数保持为零；缺失或篡改元数据时拒绝恢复且目录内容不变。
- **AC5（F5）**：示例配置中的本地配置被复制、依赖目录被链接、匹配且确认为 ignored 的文件被补齐、Git hooks 路径与主目录一致；未声明的 `.env` 不出现。越界规则、超限复制或链接失败会阻止子 Agent 启动并报告具体规则。
- **AC6（F6）**：两个并行子 Agent 分别用相对路径读写和执行命令时，所有结果只落在各自 Worktree；测试期间进程当前目录保持不变，且 Glob/Grep 不再临时调用 `chdir`。
- **AC7（F7）**：两个 Worktree 的相同相对路径含不同内容时，文件、系统提示、项目指令和项目记忆分别返回本目录版本；检查缓存键包含规范化绝对路径。删除重建同一路径后不会返回旧内容，写入后再读可见新值。
- **AC8（F8）**：Worktree 创建与初始化完成后子 Agent 才发送第一次模型请求，请求中的受控环境含子项目、Worktree、主项目和分支绝对信息；排队时取消的任务没有创建目录。
- **AC9（F9）**：正常完成、轮次受限、失败和取消四种终态都会执行一次退出；状态和通知均能观察到工作区路径、分支及处置原因，清理错误不改写原任务终态。
- **AC10（F10）**：暂存修改、未暂存修改和未跟踪文件分别使删除被拒绝；从创建基线新增且不被任何 `refs/remotes/*` 包含的 commit 即使没有 upstream 也使删除被拒绝。
- **AC11（F10）**：新增 commit 被任一远端跟踪引用包含后不再判定为未推送；远端检查失败时保守保留。初始化声明产生的 ignored 文件或链接不会单独造成脏状态。
- **AC12（F11）**：安全删除只移除匹配元数据的托管 Worktree、对应临时分支和元数据；伪造元数据、仓库不符、目录外路径、活动租约或 Git 列表不匹配均被拒绝且目标内容不变。
- **AC13（F12）**：无修改且无未推送 commit 的任务结束后目录自动消失；有修改或未推送 commit 时目录保留，结果提供绝对路径与准确原因且不执行 merge、commit 或 push。
- **AC14（F13）**：使用可控时钟构造未满 7 天和超过 7 天的候选，默认只检查后者；配置其他正整数天数后边界随之变化。
- **AC15（F13）**：后台清理对路径过滤、归属过滤和 Git/变更过滤各准备一个失败候选，全部跳过；合法过期且安全的候选被删除，单个失败不影响后续候选。
- **AC16（F14）**：并发创建同名 Worktree 只产生一个受控结果；运行中的租约不会被退出或后台清理删除；重复退出与重复清理不删除无关分支。
- **AC17（F15）**：共享定义式角色和 Fork 式子 Agent 保持使用主项目目录，Agent 工具 schema 与现有调用方式不变，普通 Agent、Skill、Hook、MCP 和权限回归测试通过。
- **AC18（N2、N6）**：Windows 与 POSIX 路径测试均通过，所有产品代码扫描未发现工作目录切换；不支持目录链接的环境返回明确初始化失败。
- **AC19（N4、N5）**：超长名称、过量初始化文件、超大复制量、Git 超时和过多清理候选都在配置上限内终止；快速恢复零 Git 调用，后台清理线程可在关闭时限内停止。
- **AC20（端到端）**：主 Agent 在同一仓库启动两个 `isolation: worktree` 的定义式子 Agent 并让它们同时修改同一路径；两边各自看到自己的内容，主目录不变。一个干净任务自动清理，另一个带修改的任务保留并可按结果路径检查。
