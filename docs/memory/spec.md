# 会话恢复与分层记忆 Spec

## 背景

FlickCode 当前的会话历史只存在于运行中的内存中。新会话无法自动获得项目规则、既往项目知识或用户偏好；中断后的对话也不能可靠恢复。因此 Agent 每次启动都需要重新了解同一项目和同一用户的工作方式。

本章在不引入向量数据库或检索系统的前提下，建立两层记忆：

- 工作记忆：按项目保存的会话 JSONL，可由用户显式恢复。
- 长期记忆：项目级与用户级自动笔记及其受限大小的索引，在处理请求前注入上下文。

新会话启动时只自动加载项目指令和长期记忆，**不得**自动续接任何历史会话。用户通过 `/sessions` 查看可恢复会话，并通过 `/resume <会话ID>` 明确选择恢复目标。

## 目标

- 让每次请求在发送给模型前都能获得适用的项目指令和长期记忆。
- 将会话安全、低开销地追加保存，并在用户明确选择后恢复为合法的对话历史。
- 在 Agent Loop 自然结束后异步提炼可复用知识，不阻塞用户看到最终回复。
- 使所有本地文件读取、引用和清理行为具备明确的安全边界与可诊断结果。

## 功能需求

### F1：分层项目指令加载

系统在创建会话时，按以下来源加载手写 Markdown 指令：

1. 用户目录 `~/.flickcode/` 中的指令文件；
2. 项目根目录中的指令文件；
3. 项目根目录 `.flickcode/` 中的指令文件。

三层来源均可缺省。拼接后的提示文本必须使项目根级和 `.flickcode/` 项目级内容位于用户级内容之前，使项目级规则具有更高的模型指令优先级；同一层内保持预定义且稳定的加载顺序。

每个指令文件可使用 `@include <相对路径>` 引入其他 Markdown 文件。系统必须：

- 只解析相对于当前指令文件的相对路径；
- 限制引用嵌套深度；
- 在一次加载中使用已访问文件集合防止循环引用和重复展开；
- 拒绝会解析到项目根目录之外的项目级引用，或用户 `.flickcode` 目录之外的用户级引用；
- 对不存在、不可读、循环、深度超限或越界引用报告可诊断信息，并继续加载其余合法内容。

### F2：会话 JSONL 归档与查询

每个项目的会话归档保存在项目 `sessions` 目录中；一个会话对应一个 JSONL 文件。新会话 ID 必须为 `YYYYMMDD-HHMMSS-xxxx` 格式，其中随机后缀避免同一秒创建冲突。

每次可持久化的会话事件按 JSONL 追加写入，已写入的历史不得被重写。单条追加失败必须向调用方报告，且不得破坏内存中的当前会话。

系统不得维护额外的会话 meta 文件。`/sessions` 所需的会话 ID、标题、消息数、最后活动时间及可恢复状态必须直接扫描相应 JSONL 推导；扫描单个异常文件时不能影响其他会话的列出结果。

`/sessions` 展示当前项目可恢复会话的稳定列表，至少包括会话 ID、推导出的标题、消息数、最后活动时间和不可恢复原因（如有）。

### F3：显式会话恢复与历史修复

新会话启动时，系统只自动注入 F1 的项目指令和 F5 的长期记忆；不得自动选择、读取或恢复最近会话。

用户可通过 `/resume <会话ID>` 显式恢复当前项目中指定的会话。恢复成功后，该会话历史成为后续请求的工作记忆；恢复失败时，不得替换当前内存历史。

恢复器读取 JSONL 时必须按以下规则构造可发送给 Provider 的历史：

- 跳过无效 JSON、字段不完整或无法识别的单行记录，并记录跳过原因和行号；
- 保持合法消息的原始顺序；
- 若 assistant 工具调用之后缺少对应工具结果，截断该未完成工具调用及其后的记录，避免发送不合法的工具调用序列；
- 恢复后的历史超出当前上下文预算时，先调用现有的上下文压缩机制尝试压缩一次；压缩后仍超限时，恢复失败并保留当前内存历史；
- 恢复会话距离当前时间超过预设阈值时，在历史中插入一条明确的时间跨度提醒，提示模型可能需要重新确认外部状态；
- 将恢复时的跳过、截断、压缩、时间提醒等结果返回给用户界面或命令调用方。

`/resume` 只能定位当前项目 `sessions` 目录内、名称与会话 ID 格式匹配的文件；不得接受任意路径或访问目录外的文件。

### F4：过期会话清理

系统定期清理最后活动时间早于 30 天的会话 JSONL。清理仅作用于当前项目 `sessions` 目录中名称与会话 ID 格式匹配的普通归档文件，且每个候选文件必须在删除前根据其自身内容或文件时间确认过期。

清理在启动或新建会话的受控时机运行，单个文件的读取或删除失败应记录诊断但不能阻止会话启动。清理不得删除仍在使用的当前会话，也不得删除不符合会话命名规则的用户文件。

### F5：长期记忆文件与预请求注入

自动笔记分别保存为用户级和项目级两套 Markdown 文件：

- 用户级笔记位于 `~/.flickcode/memory/`，供该用户所有项目使用；
- 项目级笔记位于项目 `memory/` 目录，仅供当前项目使用。

每条笔记为一个带 frontmatter 的 Markdown 文件，类别仅限：用户偏好、纠正反馈、项目知识、参考资料。frontmatter 至少包含类别、创建时间和最后更新时间；正文记录可供后续会话使用的事实、偏好或引用说明。

每套笔记维护一份 Markdown 索引文件，索引内容在每次用户请求发送给模型前加载并注入上下文，使 Agent 如同已读过这些记忆。项目级索引必须在用户级索引之前注入。每份索引均不得超过 200 行和 25 KB；超出任一限制时，更新流程必须将其压缩或裁剪至限制内，同时保留可追溯的笔记文件。

索引或单条笔记不可读时，系统应报告诊断并继续使用其余可用记忆；长期记忆加载失败不得阻止正常请求。

### F6：Agent Loop 自然结束后的异步笔记更新

仅当 Agent Loop 以模型给出最终回复、且该最终回复不包含工具调用的方式自然结束时，系统异步调用 LLM 评估本轮会话，并更新 F5 的项目级和用户级笔记及索引。

异步记忆更新必须满足：

- 不阻塞最终回复、会话落盘或下一轮用户输入；
- 只使用本轮可用的会话内容和已有笔记上下文；
- 由 LLM 判断是否值得记录，以及与既有笔记是否重复、冲突或需要合并；
- 只写入四个允许类别中的内容；
- 分别更新用户级和项目级存储，不得把仅适用于项目的知识写入用户级记忆；
- 更新失败只产生可诊断记录，不得影响已完成的 Agent 回复；
- 因 Provider 错误、达到迭代上限、被用户取消或最终回复带工具调用而结束时，不得触发更新。

## 非功能需求

### N1：可靠性与可恢复性

会话采用追加式 JSONL：进程崩溃最多影响正在写入的最后一行，恢复时该坏行可被安全跳过。任何读取、解析、压缩、写入或清理失败都必须保留尚可用的数据，并提供足以定位问题的诊断信息。

### N2：安全边界

项目级指令引用、会话恢复和清理均不得访问项目专用目录之外的文件；用户级记忆和指令均不得访问用户 `.flickcode` 专用目录之外的文件。用户输入不得通过会话 ID 或 include 路径绕过这些限制。

### N3：性能与上下文预算

会话事件以追加写实现，避免为每条消息重写完整历史。每次请求仅注入受上限约束的两份记忆索引，而不是扫描并注入所有笔记原文。自动笔记更新在后台执行，不能使前台回复等待额外 LLM 调用。

### N4：兼容性

未配置任何指令、归档或记忆文件时，现有聊天和 Agent Loop 行为应保持可用。普通聊天可使用 F1 和 F5 的预请求注入；只有 Agent Loop 满足 F6 的自然结束条件时才触发自动笔记更新。

### N5：可测试性

指令优先级、include 防护、JSONL 解析修复、恢复后的上下文压缩、时间提醒、过期清理、索引上限、预请求注入及异步更新触发条件必须能够通过不依赖真实 LLM 的自动化测试验证。LLM 参与的笔记决策应通过可替换的测试客户端验证输入和写入结果。

## 不做的事

- 不自动恢复最近一次或任何历史会话。
- 不实现向量数据库、嵌入生成、RAG 检索或语义相似度检索。
- 不实现多用户或团队记忆共享、同步、权限协作或云端存储。
- 不为会话维护独立 meta/索引数据库或单独元数据文件。
- 不将所有历史笔记正文无差别注入模型上下文。
- 不改变既有上下文压缩策略的基本语义，只在恢复超预算时复用其一次压缩能力。

## 验收标准

- AC1：三层指令存在时，构建出的系统提示中两个项目级来源均位于用户级来源前；缺失任一来源不会阻断启动。
- AC2：嵌套 include 可按稳定顺序展开；循环、越界、不可读和超深引用被拒绝并产生诊断，其余内容仍被加载。
- AC3：新会话创建的归档文件名符合 `YYYYMMDD-HHMMSS-xxxx`，后续事件为 JSONL 追加记录；无需 meta 文件即可由 `/sessions` 列出 ID、标题、消息数和最后活动时间。
- AC4：启动新会话不会恢复旧消息；`/sessions` 能显示当前项目的会话；`/resume <会话ID>` 只恢复用户指定的合法会话。
- AC5：恢复含坏 JSONL 行的会话时跳过坏行；存在未配对工具调用时，在该调用前截断；恢复结果始终是 Provider 可接收的消息序列。
- AC6：恢复历史超出预算时恰好尝试一次上下文压缩；若仍超限，当前会话内存历史不变并显示恢复失败原因。
- AC7：恢复间隔超过阈值的会话会获得一条可见的时间跨度提醒；未超过阈值时不插入该提醒。
- AC8：超过 30 天且符合会话命名规则的归档会在清理时删除；不匹配命名规则、未过期或当前正在使用的文件不会删除。
- AC9：项目级与用户级记忆各自独立存放，均为带 frontmatter 的笔记与单份索引；每份索引不超过 200 行及 25 KB，并且在用户请求发送前按项目级优先顺序注入。
- AC10：Agent Loop 以无工具调用的最终回复自然结束后，最终回复先返回给用户，笔记更新在后台开始；其他结束原因不触发自动笔记更新。
- AC11：笔记更新可由 LLM 合并或拒绝重复信息；更新错误不会改变最终 Agent 回复或阻止下一轮会话。
- AC12：所有文件边界、解析修复、过期清理和异步触发条件均有不依赖真实 Provider 的自动化测试。
