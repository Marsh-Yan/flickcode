# FlickCode Skill 系统 Spec

## 背景

FlickCode 已具备工具注册、每轮环境上下文重建、斜杠命令、主会话持久化和上下文管理能力，但可复用的 AI 操作仍需用户反复输入相同提示词。所有工具长期同时暴露给模型，也会增加无关工具干扰，降低工具选择准确率。

本功能引入 Skill：将一项可复用操作的元信息、SOP 指令及可选专属工具封装为 Markdown 能力包。系统启动时只暴露 Skill 名称和一句说明，真正需要时才加载完整内容，以控制上下文和工具规模。

## 目标

- 让用户通过 Markdown 文件定义、复用和覆盖 AI 操作。
- 按项目、用户、内置三级来源发现 Skill，并以项目优先级最高。
- 启动阶段只提供 Skill 摘要，需要时再加载完整 SOP 和专属工具。
- 支持多个 Skill 同时激活，并在后续每轮环境上下文中持续生效。
- 将当前可见工具收窄为已激活 Skill 白名单的并集，同时始终保留系统级 Skill 加载能力。
- 支持共享主会话和独立子会话两种执行方式。
- 让 Skill 自动成为斜杠短命令，并在运行期间惰性热更新。
- 提供 `commit`、`review`、`test` 三个可参考和直接使用的内置样板。
- 为以后增加市场分发和版本管理保留扩展边界，但本阶段不实现这些能力。

## 功能需求

### F1：Skill 定义格式

每个 Skill 必须包含 YAML frontmatter 和非空 Markdown 正文。

frontmatter 包含：

- `name`：唯一名称，同时作为默认斜杠命令名；仅允许小写字母、数字和连字符，并以字母开头。
- `description`：非空的单行说明。
- `tools`：可见工具白名单，允许为空。
- `mode`：`shared` 或 `isolated`。
- `history`：独立模式携带的最近完整对话轮数，必须是非负整数；共享模式不得设置。
- `model`：可选，仅独立模式允许设置；未设置时继承主会话模型。

Markdown 正文是完整 SOP。正文中的所有 `{{input}}` 均替换为调用者传入的原始内容；正文未包含占位符时保持不变。

### F2：单文件与目录型 Skill

系统必须支持：

- 单文件 Skill：三级 Skill 目录直属的任意 `*.md` 文件。
- 目录型 Skill：三级 Skill 目录的直属子目录，入口固定为 `SKILL.md`。
- 目录型 Skill 可以携带工具 schema 和实现脚本；缺少入口、schema 无效或实现文件缺失时，整个能力包视为解析失败。
- 目录型 Skill 声明的专属工具只能由其自身白名单引用，不建立跨 Skill 的隐式工具依赖。

### F3：三级发现与覆盖

系统从以下位置发现 Skill：

1. 项目级 `.flickcode/skills/`
2. 用户级 `~/.flickcode/skills/`
3. 安装包内置目录

同名 Skill 按“项目 > 用户 > 内置”覆盖。只有成功解析的定义参与覆盖；高优先级定义解析失败时，应跳过该定义并回退到下一份有效定义。

单个文件或能力包解析失败不得阻断其他 Skill。系统必须记录来源、失败原因和实际采用的回退定义。同一级出现重复名称时，该名称在该级的定义均不参与覆盖，并报告冲突。

### F4：启动发现与摘要注入

启动时系统只向 Agent 提供有效 Skill 的名称和一句说明，不注入完整 SOP，也不加载实现脚本。

启动阶段还必须：

- 建立有效 Skill 目录。
- 为有效 Skill 注册斜杠短命令和补全项。
- 在所有基础工具、MCP 工具及 Skill 工具声明完成发现后校验白名单。
- 白名单引用不存在的基础或 MCP 工具时，启动必须失败并指出 Skill、工具名和来源。
- Skill 自带工具只有在 schema 与实现均有效时才算存在。
- 系统级 Skill 加载工具始终存在，不参与白名单校验和裁剪。
- 有效 Skill 与保留系统命令重名时启动失败；现有 `/review` 例外，因为其行为迁移到内置 `review` Skill。

### F5：按需加载

系统必须提供不受白名单限制的内置 Skill 加载工具。Agent 可以根据启动时看到的名称和说明，按需请求加载指定 Skill。

加载必须是原子的：

- 先刷新目录并解析当前有效定义。
- 替换 `{{input}}`。
- 校验执行模式、工具和可选模型。
- 加载完整 SOP 与本 Skill 的专属工具。
- 所有步骤成功后才改变激活状态。
- 失败时保留原有激活状态和工具集合，并返回可诊断错误。

通过斜杠短命令调用与通过加载工具调用必须使用同一加载语义。同名 Skill 再次加载时更新其定义和 `{{input}}` 绑定，不产生重复激活项。

### F6：激活状态与上下文钉入

共享模式 Skill 激活后必须持续存在于当前主会话，多个 Skill 可以同时激活。

每次向模型发起请求时，系统必须在环境上下文的显眼固定区域插入完整的“已激活 Skill”区块：

- 位于通用内置指导之前。
- 每个 Skill 有清晰名称和边界。
- 顺序按首次激活顺序保持稳定。
- 再次加载同名 Skill 只更新原位置内容。
- 每轮重建环境上下文时都重新插入，不能依赖旧消息偶然保留 SOP。

### F7：工具白名单

没有 Skill 激活时，Agent 保持当前默认工具集合，并始终可使用 Skill 加载工具。

至少一个共享 Skill 激活后，当前可见工具必须收窄为：

```text
所有已激活 Skill 白名单的并集 + 系统级 Skill 加载工具
```

同时满足：

- 未列入并集的基础和 MCP 工具不发送给模型，也不能被模型调用。
- 未激活 Skill 的专属工具不可见、不可调用。
- 目录型 Skill 的每个专属工具都必须列入自身白名单。
- 多个专属工具名称存在歧义或冲突时，启动阶段必须报告并拒绝进入会话。
- 白名单只控制工具可见性，不绕过现有权限确认、沙箱或风险策略。
- 新 Skill 加载成功后，工具并集在同一 Agent 执行循环的下一次模型请求中生效。

### F8：共享模式执行

共享模式 Skill 在当前主会话内执行：

- 斜杠调用先激活 Skill，再把调用参数作为当前用户意图交给 Agent。
- Agent 主动调用加载工具后，可以在同一轮后续迭代中使用新 SOP 和工具。
- 模型响应、工具调用和工具结果全部保留在主历史中。
- Skill 持续激活，直到会话被重置。
- 共享模式始终使用主会话当前模型，不接受 Skill 级模型覆盖。

### F9：独立模式执行

独立模式 Skill 每次调用都创建新的子会话：

- 子会话只激活本次目标 Skill，不自动继承父会话已激活的其他 Skill。
- 携带父会话最近 `history` 个完整轮次；`0` 表示只携带本次调用。
- 一个完整轮次包括用户消息、助手响应以及从属于该轮的工具调用和结果，不得截断工具协议链。
- 子会话使用目标 Skill 的工具白名单，并始终保留 Skill 加载工具。
- `model` 存在时仅覆盖该子会话模型，否则继承父会话模型。
- 父会话等待子会话执行结束，再接收包含结果、改动、失败和后续事项的摘要。
- 主历史只保留调用信息和回流摘要，不复制子会话完整过程。
- 子会话必须单独持久化，并记录父会话标识、目标 Skill、开始与结束状态。
- 子会话中加载或激活其他 Skill 不改变父会话状态。

### F10：动态斜杠命令

每个有效 Skill 自动注册为 `/<name>`：

- 命令帮助显示 Skill 说明、执行模式和参数用法。
- Tab 补全与启动摘要使用同一有效 Skill 目录。
- 原始命令参数完整传给 `{{input}}`，不得折叠内部空格或换行。
- 共享模式命令在主会话中执行。
- 独立模式命令创建子会话并将摘要显示及记录到主会话。
- 无参数调用必须允许；此时 `{{input}}` 替换为空字符串。
- 原有硬编码 `/review` 迁移为内置 `review` Skill，不再重复注册。

### F11：惰性热更新

系统必须在以下时机检查三级目录变化：

- 每次用户提交之前；
- 每次加载 Skill 之前；
- 每次生成 Skill 斜杠补全之前。

变化在下一次模型请求前生效：

- 新增和删除 Skill 会更新启动摘要对应的运行时目录、帮助和补全。
- 有效修改会更新后续加载内容。
- 已激活 Skill 被有效修改时，下一轮使用新 SOP、元信息和白名单。
- 已激活 Skill 正在写入而暂时解析失败时，保留最后一份有效快照并显示诊断。
- 已激活 Skill 被删除且没有低优先级回退定义时，在下一轮前停用并警告用户。
- 存在有效低优先级回退时，自动切换到该定义并明确报告来源变化。
- 已经开始的执行使用启动时快照，不被中途文件修改打断。

### F12：会话恢复与重置

主会话必须持久化已激活 Skill 的名称、来源和 `{{input}}` 绑定。恢复会话时，系统根据当前目录重新解析这些 Skill：

- 有效时恢复激活状态。
- 来源已变化时使用当前优先级结果并报告。
- 已不存在或无有效定义时跳过并警告。
- 不从归档中执行旧的 Skill 脚本。

新增 `/reset` 命令，用于：

- 归档当前主会话；
- 清除主历史、计划上下文和全部已激活 Skill；
- 卸载不再被使用的专属工具；
- 创建新的主会话归档。

现有 `/clear` 继续只清理终端显示，不修改历史或 Skill 状态。

### F13：错误边界与诊断

- 单个 Skill 的 YAML、字段、正文或能力包解析错误只跳过该定义。
- 启动白名单引用不存在工具、专属工具重名或保留命令冲突属于致命配置错误。
- 加载、热更新和执行错误必须指出 Skill 名称、来源和失败阶段。
- 一个 Skill 失败不得清除其他已激活 Skill。
- 独立模式失败时仍须结束并持久化子会话，同时向主会话回流失败摘要。
- 诊断不得泄露工具环境变量、凭据或脚本中的敏感配置。

### F14：内置样板

安装包必须提供三个遵循相同格式和加载规则的内置 Skill：

- `commit`：共享模式样板。
- `review`：独立模式样板，并接管原 `/review` 入口。
- `test`：共享模式样板。

三个样板必须具有可直接使用的 SOP、最小工具白名单和清晰说明，并共同展示单文件与目录型能力包的推荐写法。项目级或用户级同名 Skill 可以按正常优先级覆盖它们。

## 非功能需求

### N1：确定性

- 相同目录内容必须产生相同的有效 Skill 目录、覆盖结果、斜杠命令和工具集合。
- 发现、诊断、摘要注入及激活 Skill 的展示顺序必须稳定。
- 不得依赖文件系统返回顺序决定覆盖或冲突结果。

### N2：本地发现与上下文效率

- Skill 发现、解析、覆盖和补全不得调用模型或访问网络。
- 未激活 Skill 只能占用名称和一句说明所需的上下文。
- 无文件变化时，惰性热更新不得重复加载实现脚本。
- 独立模式不得把完整子会话复制进主模型上下文。

### N3：故障隔离与原子性

- 单个无效 Skill 不得影响其他有效 Skill。
- 目录刷新、激活、热更新和工具集合切换必须以完整快照为边界。
- 模型不得看到一半更新的 SOP、schema 或工具集合。
- 运行中的 Skill 不受中途文件修改影响。

### N4：安全性

- 启动扫描、元信息解析、schema 校验和 Skill 激活本身不得执行实现脚本。
- 专属实现脚本只在模型明确调用对应工具时执行。
- 专属工具继续受现有权限确认、黑名单、沙箱和高风险操作规则约束。
- Skill 包不得通过相对路径、符号链接或引用逃出自身目录读取实现资源。
- 错误、状态和归档不得泄露凭据、环境变量值或敏感配置。
- 从归档恢复时只恢复声明状态，不执行归档中保存的代码或旧脚本。

### N5：会话隔离

- 独立模式子会话的消息、工具状态、模型覆盖和 Skill 激活不得修改父会话对应状态。
- 父会话只接收明确规定的摘要和调用记录。
- 子会话失败、取消或超时后仍应留下完整的可诊断终态。

### N6：兼容性

- 必须兼容现有 Anthropic 与 OpenAI Provider 的工具调用格式。
- TUI 和非交互管道输入必须共享相同的 Skill 发现、加载和斜杠执行语义。
- 不得改变 `/clear`、会话恢复、上下文压缩、权限处理及普通非 Skill 对话的既有行为。
- 没有安装任何自定义 Skill 时，除新增内置样板、加载工具和 `/reset` 外，普通 Agent 行为保持兼容。
- 实现继续满足项目声明的 Python 3.8+ 运行环境。

### N7：可观察性

系统诊断必须能够展示：

- 每个有效 Skill 的实际来源和被覆盖来源；
- 被跳过定义及原因；
- 当前已激活 Skill、执行模式和绑定来源；
- 当前工具白名单并集；
- 最近一次热更新结果；
- 独立子会话与父会话的关联和结束状态。

这些信息应接入现有帮助、状态或诊断能力，不要求读取内部文件才能判断运行状态。

### N8：可测试性

- 目录发现、覆盖、解析、占位符、热更新和白名单计算必须可使用临时目录与假工具注册表测试。
- 共享与独立执行必须可使用假 Provider 验证，不依赖真实 API。
- 子会话持久化、恢复和摘要回流必须可确定性复现。
- 测试必须覆盖 Windows 与 POSIX 路径语义，不依赖特定终端界面。
- 三个内置样板必须经过与用户 Skill 相同的解析和校验流程。

### N9：可扩展性

- Skill 定义解析、来源发现、激活状态、执行模式和专属工具适配之间必须保持清晰边界。
- 后续增加分发来源或版本信息时，不应改变本阶段 Skill 正文和核心 frontmatter 的含义。
- 本阶段不得为尚未实现的市场功能引入远程依赖。

## 不做的事

本阶段明确不包含：

- Skill 市场、远程搜索、下载、安装、发布或同步。
- 语义化版本、依赖解析、升级策略、锁文件和兼容性协商。
- Skill 签名、作者身份、信誉系统或远程供应链验证。
- `{{input}}` 之外的命名参数、条件、循环、表达式或完整模板语言。
- Skill 之间的依赖声明、自动级联加载或跨包复用专属工具。
- 为共享模式 Skill 切换模型或协调多个模型声明。
- 单独停用某个已激活 Skill 的用户命令；本阶段统一通过 `/reset` 清除激活状态。
- 将独立子会话作为可继续交互或手动恢复的普通会话；本阶段仅持久化用于审计和诊断。
- 后台定时运行、并发调度、队列、重试编排或长驻任务。
- 图形化 Skill 编辑器、向导或可视化管理界面。
- 递归扫描任意深度的 Skill 目录；只识别约定目录的直属 Markdown 文件和直属能力包目录。
- 自动生成、自动修改或自动修复用户 Skill 文件。
- 新建一套绕过现有权限与沙箱的脚本运行环境。
- 改变普通工具、MCP、Prompt、命令、会话和记忆模块在无 Skill 场景下的核心语义。

## 验收标准

- **AC1 — 定义与占位符**
  给定合法的共享模式和独立模式 Markdown 样例，系统能读取全部规定字段；调用时正文中每个 `{{input}}` 都被原样替换。非法名称、缺失字段、空正文、共享模式声明 `history` 或 `model` 时，该定义被跳过并显示原因。

- **AC2 — 两种能力包**
  三级目录中的直属 `*.md` 和含 `SKILL.md` 的直属目录都能被发现。目录型 Skill 的 schema 无效或实现文件缺失时，整个包被跳过，其他包仍正常可用。

- **AC3 — 优先级与回退**
  在三个层级放置同名 Skill 时，项目级生效；删除项目级后用户级生效；删除用户级后内置生效。把高优先级文件改为无效内容后，系统跳过它并采用下一份有效定义。同一级同名冲突产生明确诊断且结果不依赖扫描顺序。

- **AC4 — 两阶段加载**
  启动后的模型上下文只包含有效 Skill 的名称和一句说明，不含任一完整 SOP 或实现脚本内容。加载某个 Skill 后，下一次模型请求能看到该 Skill 的完整 SOP 和允许的专属工具。

- **AC5 — 启动白名单校验**
  将不存在的工具名写入任一有效 Skill 白名单后，启动立即失败，并显示 Skill 名、工具名和来源。Skill 加载工具始终出现在模型工具列表中，即使激活 Skill 的白名单未声明它。

- **AC6 — 原子加载**
  对合法 Skill 执行加载后，SOP、绑定输入、激活状态和工具集合同时生效。让其中任一步骤失败后，原激活列表、SOP 和工具集合均保持不变，并得到可诊断错误。

- **AC7 — 多 Skill 持续激活**
  依次加载两个共享模式 Skill，连续发送多轮普通消息；每轮模型请求都包含两个完整 SOP，顺序稳定。再次加载其中一个时，其位置不变但绑定输入和内容更新，不产生重复区块。

- **AC8 — 工具白名单并集**
  未激活 Skill 时，模型看到默认工具集合和加载工具。激活两个白名单不同的 Skill 后，模型只看到两个白名单的并集及加载工具；尝试调用并集之外的工具时调用被拒绝。未激活 Skill 的专属工具不可见。

- **AC9 — 共享模式历史**
  通过斜杠命令和加载工具分别调用共享模式 Skill；SOP 在当前会话生效，响应、工具调用和结果进入主历史，并能被后续普通对话引用。执行过程使用主会话模型。

- **AC10 — 独立模式隔离**
  配置 `history: 2` 的独立 Skill 被调用后，子会话只包含父会话最近两个完整轮次、本次调用和目标 Skill；工具调用链没有被截断。指定模型只作用于子会话。执行结束后子会话单独落盘并关联父会话，主历史只出现调用记录和摘要，父会话的模型、工具和激活状态均未改变。

- **AC11 — 动态斜杠命令**
  每个有效 Skill 都能通过 `/<name>` 出现在帮助和 Tab 补全中。包含多行及连续空格的参数会完整传给 `{{input}}`。共享和独立命令分别走对应执行路径；无参数调用将占位符替换为空字符串。

- **AC12 — 有效热更新**
  程序运行期间新增、修改或覆盖 Skill 文件，无需重启；在下一次提交、加载或补全时，目录、帮助、命令、SOP 和白名单采用新有效定义。已开始的执行继续使用原快照。

- **AC13 — 无效更新与删除**
  把已激活 Skill 暂时改成无效 YAML，下一轮仍使用最后有效快照并显示诊断。删除它后，有低级定义则自动回退并报告来源变化；无回退定义则在下一轮前停用并警告。

- **AC14 — `/clear` 与 `/reset`**
  执行 `/clear` 后终端显示被清理，但主历史、计划上下文和激活 Skill 保持不变。执行 `/reset` 后旧会话已归档，新主会话标识已创建，主历史、计划上下文、激活 Skill 和不再使用的专属工具均为空。

- **AC15 — 会话恢复**
  恢复包含共享 Skill 激活记录的主会话时，系统按当前三级目录重新解析并恢复名称和绑定输入；来源变化或定义缺失时显示诊断。恢复过程不执行实现脚本或归档代码。

- **AC16 — 故障隔离与安全诊断**
  同时放置一个无效 Skill 和两个有效 Skill，启动后两个有效 Skill 仍可使用。一个 Skill 加载或执行失败不会清除另一个 Skill。独立执行失败仍生成带失败状态的子会话和主会话摘要。所有输出及归档均不出现测试凭据或环境变量值。

- **AC17 — 内置样板**
  全新安装无需用户文件即可发现并调用 `commit`、`review`、`test`。项目级同名定义能够覆盖内置版本。`/review` 只有一个注册来源，并由内置或覆盖后的 `review` Skill 执行。

- **AC18 — 入口与 Provider 兼容**
  使用假 Provider 分别从 TUI 和管道输入执行相同 Skill 场景，得到一致的发现、参数、激活、白名单和摘要结果。Anthropic 与 OpenAI 工具格式下，基础工具和目录型专属工具都能完成一次有效调用。
